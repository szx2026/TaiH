# 跨境产品 ERP 重做设计

## 目标

重做为一套面向电脑后台使用的跨境产品增长协作系统，服务“选品—开发—素材—投放测试”的完整闭环。每个产品只有一个项目档案；四个部门围绕同一项目交付、讨论、反馈和追溯，而不是在独立表格与孤立页面间切换。

本设计保留 SiteGround Cloud 部署、MySQL 数据库和 Cloudflare R2 私有对象存储的既定方向。系统使用 Laravel 服务端渲染页面，Tailwind 构建静态样式，Alpine 负责少量交互；生产环境不需要常驻 Node 服务。

## 用户与部门

| 部门 | 系统职责 | 主要权限 |
| --- | --- | --- |
| 市场研究部 | 趋势、广告库、平台商品和竞品证据；发起选品项目 | 创建项目、记录研究证据、提交至网站运营部 |
| 网站运营部 | 1688 货源、内部 SKU、规格价格、落地页 | 建立货源/SKU/页面版本；处理页面与规格反馈 |
| 内容创意部 | 视频、图片、文案与素材审核 | 查看产品资料；管理素材版本、审核及可投放状态 |
| 流量增长部 | Facebook/TikTok 等测试、指标与优化建议 | 记录测试数据；向相关部门发起反馈 |
| 管理员 | 成员、部门、整体数据和配置 | 管理成员、查看全局项目与数据接入配置 |

角色为管理员、部门负责人和成员。成员只能操作所属部门负责的交付物与反馈；管理员可查看全局。

## 信息架构与页面

### 全局结构

左侧导航固定为：工作台、产品中心、素材中心、投放中心、反馈中心、活动记录、成员与权限、数据接入。顶部显示工作空间、所属部门、当前用户与快捷新建操作。

### 工作台

工作台按登录用户的部门过滤，展示：

- 当前环节的项目和阶段进度；
- 待处理反馈与到期提醒；
- 与该部门项目关联的花费、展示、点击、CTR、转化摘要；
- 最近活动；
- 管理员的全局汇总视图。

### 产品中心

提供产品项目列表、状态/部门/市场/优先级筛选、搜索、新建项目和卡片或表格两种视图。产品项目详情是系统的核心工作区。

### 产品项目详情

详情页使用固定项目头部和六个标签：

1. 概览：阶段轨道、关键决策、交付物进度、项目健康度、关联人员和近期活动。
2. 选品与货源：调研来源、筛选理由、1688 或其他供应商信息、成本与包装信息。
3. SKU 与落地页：内部 SKU 申请/导入状态、规格、价格、落地页版本和 SKU 关联。
4. 创意素材：视频、图片、文案、参考来源、审核状态、关联 SKU/落地页和素材版本。
5. 投放测试：广告系列、素材/页面版本、花费、展示、点击、CTR、转化、CPA 和测试结论。
6. 反馈与活动：跨部门反馈、处理回复、处理状态，以及不可篡改的系统活动记录。

右侧常驻项目健康度、待确认决策、负责人和近期活动，避免用户进入多个页面才能获知阻塞项。

## 工作流

项目标准阶段依次为 `market_research`、`website_operations`、`content_creative`、`traffic_growth`。阶段不是单向锁：流量增长部可把反馈发送回网站运营部、内容创意部或市场研究部；反馈关闭不改变项目阶段，明确的阶段移交才改变阶段。

每次移交必须包含交付说明、接收部门、操作者和时间。每个阶段有最低交付物规则：

- 市场研究部提交前至少有一条研究证据；
- 网站运营部提交前至少有货源、一个可用 SKU 和落地页版本；
- 内容创意部提交前至少有一个“可投放”素材；
- 流量增长部结束一次测试前必须记录关键指标与结论。

项目状态与阶段分离：草稿、进行中、阻塞、已通过、已淘汰、已归档。

## 数据模型

`product_projects` 是聚合根。所有业务记录都带有 `product_project_id`、创建人和时间。

| 领域 | 主要记录 |
| --- | --- |
| 项目协作 | 项目、阶段移交、项目成员、关键决策、任务、活动日志 |
| 市场研究 | 研究证据、平台、来源 URL、截图/附件、趋势指标、筛选结论 |
| 开发运营 | 供应商货源、SKU、SKU 规格、内部系统 SKU 同步记录、落地页、落地页版本 |
| 内容创意 | 素材、素材版本、素材与 SKU/页面的关联、审核记录 |
| 流量增长 | 投放账户、广告系列测试、每日指标、测试结论、素材/页面表现 |
| 协作闭环 | 跨部门反馈、回复、处理状态、目标部门、关联业务记录 |

附件字节存放于私有 Cloudflare R2；MySQL 只保存对象键、文件名、MIME 类型、大小、校验值、上传人和访问策略。下载和预览使用短时签名 URL。

## 手动与自动数据入口

所有首发业务记录均保留手动新建、编辑、上传与外部链接入口。每条可自动同步的数据同时记录：来源类型、外部 ID、最后同步时间、同步状态、原始载荷摘要和“手动锁定”标记。

自动化为第二阶段能力：TikTok/Facebook 广告库、广告平台指标、内部 SKU 系统、1688/供应商信息通过 API、CSV 导入或受控采集接入。自动同步绝不覆盖已手动锁定的字段；冲突进入待处理队列。

## 反馈与活动规则

反馈必须关联项目，可选关联 SKU、落地页版本、素材或投放测试，并指定目标部门。目标部门成员可以接手、回复、标记处理中、解决或退回。所有状态变化生成活动日志；原始反馈、回复和移交记录不可删除。

## 安全与部署

- SiteGround Cloud：Laravel 应用与 MySQL；Web 根目录指向 `public`。
- `app` 子域名：启用 SSL、强制 HTTPS、应用环境变量与错误日志。
- Cloudflare R2：私有桶、S3 兼容连接、签名上传/下载；不把密钥写入代码库。
- 账号密码使用 Laravel 哈希；登录后轮换会话；管理员操作写入审计日志。
- 定时任务用 SiteGround Cron 触发 Laravel scheduler；异步同步和通知可先采用数据库队列，后续按负载升级。

## 实施策略

当前实现仅作为早期流程验证保留在 `main` 历史中。重做将在独立分支和工作区中完成，先建立统一的后台布局、设计令牌、项目中心和数据迁移兼容层；通过验收后再替换主分支体验。不会删除已有提交或用户数据。

第一阶段交付目标：专业工作台、产品中心、重构的项目详情页、部门权限、阶段移交、反馈中心和活动记录。第二阶段：R2 上传、素材中心、投放中心、批量导入和外部 API。第三阶段：自动采集、定时同步、通知和高级分析。

## 验收标准

1. 四个部门能在同一个项目详情页完成各自的手动录入和移交。
2. 任何投放结论都能追溯到素材、落地页、SKU、来源和处理反馈。
3. 用户打开工作台时，不必进入项目也能看到当前待办和阻塞项。
4. 文件从上传到访问均通过 R2 私有对象和签名 URL，数据库不保存文件字节。
5. 未授权部门不能创建或处理其他部门的记录。
6. 所有阶段移交、反馈状态和核心业务修改保留活动记录。
7. 在 SiteGround Cloud 的 PHP/MySQL 环境中可部署，生产环境不依赖常驻 Node 进程。
